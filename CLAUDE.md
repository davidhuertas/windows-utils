## What this is

Monorepo of standalone Windows 11 developer utilities. One directory per utility, no shared code, no root build system, no package manager, no test framework, not a git repo. Each utility is self-contained and installed by hand (shortcut target, terminal profile, or `source`).

Utilities:
- `git-bash-workspace-selector/` — Bash TUI that picks a workspace dir at Git Bash startup
- `jdk-path-selector/` — placeholder, empty

## Running / testing

No build, no lint, no test runner. Verify by running in Git Bash:

```bash
source git-bash-workspace-selector/ws.sh
```

`ws.sh` **must be sourced, not executed** — its whole point is `cd` + `export WS_CHOSEN_PATH` in the caller's shell. Running it as `./ws.sh` changes dir in a subshell and does nothing observable. Same for `ws-launch.sh` when used from a Windows Terminal profile.

Interactive TUI: arrows move, Enter selects, `q` quits, `e` exports current list to a file. Terminal must be a TTY (raw `read -rsn1`), so it cannot be smoke-tested through a piped/non-interactive shell — test in a real Git Bash window.

## Architecture notes that span files

**Two entry points, one engine.** `ws.sh` is the sourceable engine. `ws-launch.sh` is the Windows-shortcut wrapper: it sources `ws.sh`, then `exec /usr/bin/bash -i` to keep the window open. Anything that must survive into the user's session has to be `export`ed by `ws.sh` (currently `WS_CHOSEN_PATH`) — the wrapper's `exec` inherits env, not shell state beyond it.

**Workspace list resolution order** (`ws.sh:10-28`):
1. `$WORKSPACES_FILE` if set
2. else `.workspaces` next to the script, if it exists
3. else hardcoded `WORKSPACES` array fallback

Gotcha: an *existing but empty* `.workspaces` wins over the fallback and the script exits with "No workspaces configured." The checked-in `.workspaces` is empty on purpose — it's the user's local list, populated per machine.

**Line format** is `Name|/c/path/to/dir`. Names may contain spaces; paths must be MSYS-style (`/c/...`), not `C:\...`, since `cd` runs inside Git Bash. Parsing strips CR (Windows line endings), trims whitespace, and drops a trailing slash.

**Redraw model:** the menu is repainted by clearing exactly `#names + 4` lines with ANSI escapes. Any change to the number of lines `render_menu` prints must update `lines_to_clear` (`ws.sh:96`), or the display smears. The export branch clears `lines_to_clear + 5` because of its own prompt lines.

`set -uo pipefail` is used without `-e` deliberately — a sourced script that exits on error would kill the user's shell. Failure paths use `(return N 2>/dev/null) || exit N` so the script behaves both sourced and executed.
